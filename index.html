Situação-problema

A Sabor da Praça é uma pequena lanchonete que comercializa sanduíches, salgados, sucos e refrigerantes. Atualmente, os funcionários utilizam planilhas para registrar clientes, produtos e pedidos. Com o aumento das vendas, surgiram informações repetidas, preços desatualizados, pedidos incompletos e dificuldade para consultar registros.

O proprietário deseja substituir essas planilhas por um banco de dados organizado, confiável e fácil de manter. Sua responsabilidade será planejar, implementar e testar essa solução.

Requisitos oficiais

R01 — Clientes. Armazenar identificador único, nome e telefone de cada cliente. Nome e telefone são obrigatórios.
R02 — Produtos. Armazenar identificador único, nome e preço. Nome e preço são obrigatórios. O preço não pode ser negativo; essa regra deve ser aplicada no próprio banco.
R03 — Pedidos. Armazenar identificador único, data, situação, cliente responsável e produto solicitado. Todos são obrigatórios. As situações permitidas são Pendente, Em preparo, Entregue e Cancelado. A coluna situação deve aceitar somente esses valores, por CHECK ou outra estratégia de validação implementada no próprio banco.
R04 — Relacionamentos. Um cliente pode realizar vários pedidos; cada pedido pertence a um único cliente. Um produto pode aparecer em vários pedidos; nesta versão simplificada, cada pedido contém exatamente um produto. Não implemente pedidos com múltiplos produtos.
R05 — Integridade. Não cadastrar pedidos vinculados a clientes ou produtos inexistentes. Utilizar identificadores únicos, chaves e restrições adequadas. Clientes e produtos vinculados a pedidos não podem ser excluídos enquanto esses vínculos existirem; a exclusão não deve apagar pedidos automaticamente.
R06 — Operações. Permitir cadastros, consultas, atualizações, exclusões controladas e alterações futuras na estrutura. A categoria dos produtos só será solicitada na Missão 4.

Escopo: não será necessário desenvolver aplicativo, site, estoque ou pagamentos.

3.5 — Criação do banco e das tabelas

💡 Dica técnica — Como planejar o SQL
  1. Identifique as tabelas necessárias.
  2. Defina os tipos dos atributos.
  3. Determine campos obrigatórios e chaves.
  4. Identifique restrições de valores e de relacionamentos.

Execute e confira os resultados no MySQL Workbench.

⌨️ Consultar sintaxe SQL — Criação e restrições

Criação:

CREATE DATABASE nome_banco;
USE nome_banco;

CREATE TABLE nome_tabela (
    id INT PRIMARY KEY AUTO_INCREMENT,
    coluna1 VARCHAR(100) NOT NULL,
    coluna2 DECIMAL(10,2)
);

Fragmento de chave estrangeira:

FOREIGN KEY (nome_coluna_fk)
    REFERENCES tabela_referenciada(coluna_pk)

Fragmento de validação:

CHECK (nome_coluna >= valor_minimo)

Esses fragmentos devem ser posicionados corretamente no CREATE TABLE, com as vírgulas necessárias. Utilize MySQL 8.0.16 ou posterior para aplicação de CHECK; em versões anteriores, a cláusula pode ser ignorada. Colunas de FKs precisam de tipos compatíveis.
